1. VPN Communication Protocols
1.1. SE-VPN Protocol
Ranz VPN implements the "SoftEther VPN Protocol (SE-VPN Protocol)" of SoftEther VPN. SE-VPN protocol encapsulates any Ethernet packets into an HTTPS (HTTP over TLS) connection. Therefore SE-VPN protocol can communicate beyond firewalls even if the network administrator configured the firewall to block traditional VPN packets. SE-VPN protocol is designed and implemented to comply with TLS (RFC 5246 and RFC 8446) and HTTPS (RFC 2818). However, it sometimes behaves differently from the RFCs. If you are a network administrator and want to block SE-VPN protocol on the firewall, you can adopt a "white-list" policy on the firewall to filter any TCP or UDP packets on the border except explicitly allowed packets towards specific web sites and servers. A new Ranz VPN Server (one with no configuration file yet) listens on TCP ports 443 and 5555. Both ports carry VPN sessions and administration connections.

1.2. UDP Acceleration
Ranz VPN has the UDP Acceleration function. If the two ends of a VPN session detect that a UDP channel can be established between them, UDP will be used automatically. By this function, throughput increases. Ranz VPN uses direct UDP packets only: it has no "UDP Hole Punching" and uses no cloud server to establish the UDP channel. If an administrator sets a STUN server in the "StunServer" item of the "ServerConfiguration" folder of the configuration file, the server sends STUN requests to that server to learn its public UDP address. "StunServer" is empty by default, and then no STUN request is sent. UDP Acceleration can be disabled at any time on the client side.

1.3. Functions Not Included
Ranz VPN contains only the SE-VPN protocol of SoftEther VPN. It does not contain VPN over ICMP, VPN over DNS, R-UDP, OpenVPN, L2TP/IPsec, IPsec/IKE, EtherIP, SSTP, WireGuard or PPP. It also does not contain SoftEther VPN Client, SoftEther VPN Bridge, the GUI programs, the installers, the Virtual NAT and Virtual DHCP functions (SecureNAT), RADIUS authentication, smart-card (PKCS#11) authentication, clustering, JSON-RPC or the HTML5 web console. The notices of SoftEther VPN about these functions do not apply to Ranz VPN.


2. Ranz VPN Software
2.1. Ranz VPN Server
Ranz VPN consists of headless programs for Windows 10, Windows Server 2016 and later, on x64 and arm64: vpnserver.exe (the VPN server), vpncmd.exe (the command-line administration tool) and vpntest.exe (diagnostics). There is no GUI and no installer. vpnserver.exe runs as the Windows service "Ranz VPN Server", which "vpnserver /install" registers, or as an ordinary process (section 2.3). It keeps its configuration file "ranz_server.config", the backups of that file and its logs in the folder of vpnserver.exe, and some data under the registry key "Software\Hanzcodes\Ranz VPN".

2.2. Local Bridge
If you use the "Local Bridge" function (for example the vpncmd commands BridgeCreate or BridgeDeviceList), Ranz VPN Server installs the SeLow driver on the computer. SeLow is a kernel-mode NDIS protocol driver that sends and receives Ethernet packets on the physical network adapter. The driver is digitally signed by Microsoft (Windows Hardware Compatibility Publisher). It exists for x64 only, so Local Bridge is not available on arm64. Once installed, the driver starts together with Windows. It stays installed after you remove Ranz VPN; you can remove it manually.

2.3. Running without the Windows Service
"vpnserver /usermode" runs Ranz VPN Server as an ordinary process of the user who starts it, without the Windows service and without system administrator privileges. In this mode it shows no window and no task-tray icon. Therefore, for example, an employee could run Ranz VPN Server on a computer in the office network and connect to it from home. No system administrative privileges are required for this from the technical point of view. However, breaking rules of the company to run software on a computer without authority might be regarded as an unfavorable behavior. If you are an employee and the company policy prohibits installing software or making communications towards the Internet without permission, you have to obtain a permission from the network administrator or the executive officer of your company in advance. You must never run Ranz VPN Server on another person's computer without the owner's consent. Such behavior might be an offence against the criminal law.

2.4. Removal
Ranz VPN has no uninstaller. To remove it, run "vpnserver /uninstall" to stop and delete the Windows service, and then delete the program files. The configuration file, its backups and the logs stay in the folder of vpnserver.exe until you delete them. The Windows Firewall entries (section 2.6), the registry key "Software\Hanzcodes\Ranz VPN" and the SeLow driver (section 2.2) are not removed automatically. Remove them manually if you no longer need them.

2.5. Security
Set the administrator password of Ranz VPN Server (vpncmd command ServerPasswordSet) right after the first start. Until you set it, another person who can connect to the server can access it as the administrator and can set the password without your permission.

2.6. Windows Firewall
When Ranz VPN Server starts, it registers vpnserver.exe, vpncmd.exe and vpntest.exe in Windows Firewall as allowed programs. These entries remain after you remove Ranz VPN. You can remove them manually from the Control Panel of Windows.

2.7. Logs
Ranz VPN Server writes a server log, and each Virtual Hub can write a security log and a packet log (vpncmd commands LogEnable and LogPacketSaveType), into the folder of vpnserver.exe. Packet logs record headers of the packets that pass through a Virtual Hub. Together with the security logs, they can help to find the user who initiated a communication. Record and use these logs only for legitimate purposes. Do not peek at or leak them except for a rightful purpose, and protect the privacy of communication of your users.


3. Network Connections and Privacy
3.1. No Internet Services
Ranz VPN does not contain the Internet services of SoftEther VPN: Dynamic DNS, NAT Traversal, UDP Hole Punching, VPN Azure, VPN Gate, the DNS proxy cloud servers, the Keep Alive function and the automatic update notification. Ranz VPN does not depend on any server operated by SoftEther Corporation, by Hanzcodes or by another service operator, and it sends no information to them.

3.2. Connections Made by Ranz VPN Server
Ranz VPN Server accepts VPN and administration connections on its listeners. It makes outgoing connections only to hosts that an administrator configures: the destination servers of Cascade connections, the syslog server, the STUN server (section 1.2) and, when an administrator sets the server certificate (vpncmd command ServerCertSet), the address named in that certificate from which a missing intermediate CA certificate is downloaded. Host names are resolved through the DNS servers configured in Windows.
