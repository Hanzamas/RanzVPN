# Design records

Architecture decision records live in `docs/adr/`; the reasoning behind them is in the discussion log here. Statuses: Accepted = Hilmi explicitly agreed; Proposed = recommended, not yet confirmed; Draft = written up with an open question for Hilmi, the build follows its Decision section meanwhile; Superseded = overridden by a later ADR; see each ADR's status line for nuances.

## Decision records

- [ADR-0001](../adr/0001-ranz-vpn-slim-down-scope.md) — Ranz VPN 0.1 slim-down scope: the spec is issue #1 (Accepted).
- [ADR-0002](../adr/0002-ci-only-verification-no-behaviour-changing-refactors.md) — CI is the only verification loop; no behaviour-changing refactors without a test harness (Accepted).
- [ADR-0003](../adr/0003-safe-cleanup-catalogue.md) — Catalogue of safe cleanups after the tickets: the safe sweep, spec #24, ending with the one-time reformat (Accepted; items 3 and 4, file splits and per-module headers, deferred to after the harness).
- [ADR-0004](../adr/0004-l3-core-with-wintun-l2-as-optional-service.md) — L3 core on Wintun, L2 as an optional service (Superseded by ADR-0014; analysis kept for L3 networks).
- [ADR-0005](../adr/0005-transport-stack-quic-tls-noise-cdn.md) — QUIC primary, Trojan-style TLS/TCP fallback, Noise-style session layer, CDN path, stealth sidecar (Accepted 2026-10-13; AES-GCM only, new-core parameters in ADR-0022 and ADR-0023).
- [ADR-0006](../adr/0006-censorship-circumvention-tiers.md) — Censorship circumvention as a tiered edge feature (Accepted 2026-10-13; v1 targets commercial DPI, GFW-class resistance in phase 2, tier 3 is the Go mimicry sidecar of ADR-0023).
- [ADR-0007](../adr/0007-tls-stack-openssl-vs-schannel.md) — One TLS stack for the new core: Schannel and msquic+Schannel, OpenSSL dropped (Accepted; minimum OS Windows 11 / Server 2022).
- [ADR-0008](../adr/0008-windows-native-replacements.md): Windows-native replacements for SoftEther's runtime (Accepted as a principle; IOCP + USO/URO, RIO crossed out; amended 2026-10-20: SecureNAT becomes NAT in the data plane plus three egress tiers, not WinNAT; amended 2026-10-21: the http.sys row is superseded by the controller's intent API and web UI).
- [ADR-0009](../adr/0009-adapter-choice.md) — Adapters: Wintun for L3 (Accepted), TAP for L2 with Neo6 vs tap-windows6 open (Proposed), SeLow for bridging (Accepted).
- [ADR-0010](../adr/0010-routing-at-the-edge-no-in-daemon-bgp.md): Routing: Windows IP forwarding between networks/VLANs via loopback adapters, automatic overlay routes from the control plane, BGP at the edge through a GoBGP sidecar, no OSPF (Accepted; amended 2026-10-20: EVPN type-5 through `ranz-bgp`, VXLAN in the node; amended 2026-10-21: per-VRF forwarding inside the overlay, Windows IP forwarding only at a gateway's LAN edge, the `Gateway` resource is the approval).
- [ADR-0011](../adr/0011-single-node-binary-with-roles.md) — One node binary with roles and both data-path backends (Accepted with ADR-0014; amended 2026-10-19: no stock SoftEther client; 2026-10-20: the controller leaves the node binary; 2026-10-21: stock SoftEther peers return through `ranz-compat` in the Legacy phase).
- [ADR-0012](../adr/0012-remove-vpnclient-from-slim-fork-keep-cascade.md) — Remove vpnclient from the slim fork, keep cascade (Accepted, ticket #23).
- [ADR-0013](../adr/0013-selow-stays-in-slim-fork-not-in-l3-core.md) — SeLow stays: Local Bridge in the fork, L2 bridging in the new product (Accepted; amended 2026-10-20: the three egress tiers replace "WinNAT where needed").
- [ADR-0014](../adr/0014-dual-mode-networks-l2-first-class.md) — Dual-mode virtual networks, L2 switched first-class and L3 routed, one binary with both backends (Accepted; amended 2026-10-20: NAT in the data plane and three egress tiers instead of WinNAT, still no own TCP/IP stack).
- [ADR-0015](../adr/0015-nat-traversal-p2p-and-relay.md): NAT traversal, P2P and relay: libjuice ICE, libplum port mapping, Ranz's own relay role, relay-first with background upgrade (Accepted; amended 2026-10-21: libjuice and libplum are MPL-2.0, not MIT).
- [ADR-0016](../adr/0016-windows-native-runtime-thin-inline-header.md) — Windows-native runtime for Mayaqua behind one thin inline header (`Lock(x)` stays readable), wrapper flip per primitive, semantics preserved, after the harness (Accepted; amended 2026-10-13: stops after DNS and WinHTTP, CNG and Schannel move to the new core, the memory tracker stays).
- [ADR-0017](../adr/0017-roadmap-foundation-before-new-core.md) — Roadmap: slim-down, scope cuts, harness, safe sweep, table-driven RPC/vpncmd, structural refactor and Windows-native runtime, and only then the new core; old code is the oracle through the pinned `main-oracle` releases (Accepted; amended 2026-10-13: harness moved before the safe sweep).
- [ADR-0018](../adr/0018-packet-io-xdp-for-windows.md) — Packet I/O and XDP for Windows: TLS/TCP 443 fallback stays on the Windows TCP stack; QUIC gets XDP only through MsQuic (default off, Server x64 only); Local Bridge backends by attachment type (SeLow, Npcap, XDP), each XDP backend after a spike; the KM-TEST loopback adapter as the L2 adapter; QTIP opt-in for server-to-server links (Accepted; amended 2026-10-13: RIO crossed out, XDP 1.4 rule API now and eBPF later, `xdp.sys` signature to re-verify).
- [ADR-0019](../adr/0019-l2-isolation-vlans-and-policy-engine.md): New core: isolation primitives kept, full VLAN support (access/trunk ports, native VLAN, QinQ, per-VLAN limits), stateful identity-based policy engine replacing the access list (Accepted; amended 2026-10-21: default deny per network with an explicit starter rule).
- [ADR-0020](../adr/0020-release-packaging-and-listener-defaults.md): Release packaging and listener defaults for the current server: unsigned MSI built in CI, data next to the exe, uninstall keeps config, service `ranzvpnserver`, tag-driven releases, TCP 443 only with a 5555 fallback, port 80 off by default (redirect and ACME only), DNS/ICMP transports in new-core phase 2 (Accepted; amended 2026-10-22: releases are Authenticode code-signed, a self-signed certificate in CI during development).
- [ADR-0021](../adr/0021-web-admin-replacing-vpncmd.md): Web admin console and HTTP API replacing vpncmd, built now on the slim fork: `/admin` vanilla single-page app from hamcore and RPC-style `POST /api/v1/<RpcName>` JSON generated from the #28 field tables on the existing admin TLS listeners, session cookie plus CSRF token, localhost and LAN only by default with the decoy page for everyone else, 5-failure lockout, audit at `AdminDispatch`, Prometheus `/metrics`, vpncmd frozen until the UI reaches parity (Superseded 2026-10-21 by ADR-0026, ADR-0031 and ADR-0038: the controller's intent API and web UI).
- [ADR-0022](../adr/0022-new-core-platform-and-crypto.md): New-core platform: Windows 11 / Server 2022 on x64 and arm64, C17 strangler reusing Hub, Account, Sam, Logging and Cfg in-process, per-core run-to-completion with no hub-wide forwarding lock, Schannel TLS 1.3 and CNG only (AES-GCM, Noise_IK), SQLite via `winsqlite3.dll`, roles including `controller` with nanopb, the `ranz-bgp` sidecar, the eight-step strangler order, 10,000 sessions and 10 Gbps per node (Accepted; amended 2026-10-14: native-first rule and L2 backend per role; amended 2026-10-15: XDP as the default L2 backend on x64, multi-connection tunnels, TCP-over-TCP mitigations; amended 2026-10-20: the controller becomes a separate Go service with rqlite, step 6 without WinNAT, SE-VPN only through `ranz-compat`, the front door on 443; amended 2026-10-21: TCP splitting on the Windows TCP stack through WinDivert, the node identity key in the software KSP, server and controller keys in the CNG KSP, explicit Schannel key exchange groups with X25519MLKEM768 first).
- [ADR-0023](../adr/0023-security-anti-censorship-and-traffic-mimicry.md) — Security model and anti-censorship: v1 defeats commercial DPI that fingerprints VPN protocols, nation-state resistance designed now and enabled in phase 2; Noise inside TLS/QUIC, a pluggable transport interface, forward secrecy and key separation; traffic mimicry as a phase-2 Go sidecar (REALITY + uTLS over TCP 443, Edge fingerprint by default) behind a local named pipe, with active-probing resistance and two decoy modes (Accepted).
- [ADR-0024](../adr/0024-clang-cl-spectre.md) — Spectre mitigation under clang-cl: `/Qspectre` only for `cl.exe`, nothing for clang-cl and the CMake output says so, no speculative load hardening until it is measured (Draft; open question: does the server threat model need a compiler Spectre variant 1 mitigation).
- [ADR-0025](../adr/0025-vrf-4via6-and-nat-in-the-data-plane.md): VRF, 4via6 and NAT in the node's data plane: one immutable LPM table per VRF swapped atomically, one Wintun adapter per VRF with a fixed GUID, 4via6 inside each VRF's ULA /48, 1:1 NAT and SNAT in the data plane, route-target leaking, Endpoints, full mesh or hub-and-spoke, gateway HA, three egress tiers (RRAS NAT, WinNAT where free, a proxy on the Windows stack), MTU 1280 with MSS clamping, rate limits, DSCP, multicast replication (Accepted, SDN spec #176).
- [ADR-0026](../adr/0026-controller-service-and-store.md): The controller is a separate Go service (`ranz-controller`, Windows or Linux) with rqlite as its sidecar store, one member by default and 3 or 5 for HA, hashicorp/raft as the fallback, no Postgres; the node is data plane only (Accepted, SDN spec #176).
- [ADR-0027](../adr/0027-node-and-controller-synchronisation.md): Node and controller synchronisation: desired state per node by Generation, deltas against the last acknowledged Generation, acknowledgements, forwarding on the last Generation without a controller, N and N-1 schema support (Accepted, SDN spec #176).
- [ADR-0028](../adr/0028-ipam-and-overlay-dns.md): IPAM only in the controller with per-VRF pools and no DHCP inside the overlay; overlay DNS through a stub resolver on each Wintun address, NRPT for the overlay suffixes and one zone per VRF (Accepted, SDN spec #176).
- [ADR-0029](../adr/0029-policy-firewall-and-mirroring.md): One stateful policy layer compiled from tags, default deny with an explicit starter rule, a conntrack quota per VRF, FQDN rules from the stub resolver, inline inspection through hub-and-spoke, Mirrors over VXLAN (Accepted, SDN spec #176).
- [ADR-0030](../adr/0030-telemetry-and-events.md): Telemetry: counters per peer, VRF and rule, ETW on the node, Prometheus and OTLP from the controller, IPFIX last in v1, webhook events (Accepted, SDN spec #176).
- [ADR-0031](../adr/0031-intent-api-revisions-explain-and-rbac.md): Declarative intent API with `ranz apply`, revisions, diff, rollback and `--confirm`, `ranz explain` checked against the data plane, three global roles, the importer from `ranz_server.config` (Accepted, SDN spec #176).
- [ADR-0032](../adr/0032-edge-evpn-vxlan-and-vrf-lite.md): Edge: EVPN type-5 through `ranz-bgp`, VXLAN in user space on the gateway, overlap-safe handoff by EVPN only, VRF-lite for non-overlapping prefixes on LBFO or one NIC per VRF (Accepted, SDN spec #176).
- [ADR-0033](../adr/0033-capabilities-per-node.md): Nodes report Capabilities (SKU, architecture, Hyper-V, LBFO, SeLow, XDP, egress tier); the controller refuses intent a node cannot honour; core features work on every SKU (Accepted, SDN spec #176; since 2026-10-21 also the 5555 fallback of ADR-0035).
- [ADR-0034](../adr/0034-defaults-at-first-install.md): A first install works like a mesh VPN: VRF `default` with an automatic pool, full mesh, overlay DNS and an explicit allow-all starter rule (Accepted, SDN spec #176).
- [ADR-0035](../adr/0035-front-door-on-443.md): The front door on TCP 443 peeks the first bytes and hands each socket to its owner with `WSADuplicateSocketW`; UDP 443 stays QUIC only (Accepted, SDN spec #176; amended 2026-10-21: port 80 through HTTP.sys URL reservations where HTTP.sys holds it, 5555 when 443 is taken).
- [ADR-0036](../adr/0036-licensing.md): Licensing: proprietary EULA, Personal, Business and Enterprise tiers, perpetual fallback after 12 paid months, two years of security fixes, licence check in the controller, third-party obligations (Accepted, SDN spec #176; amended 2026-10-22: the protection, anti-tamper and activation model, with online activation and a server-delivered Enterprise key).
- [ADR-0037](../adr/0037-legacy-phase-ranz-compat-and-industrial-gateways.md): The Legacy phase after v1: `ranz-compat` (frozen slim-fork Cedar with OpenSSL) for SE-VPN, OpenVPN, WireGuard, L2TP/IPsec, SSTP, EtherIP and L2TPv3, and a `legacy` role for industrial gateways, XOT first (Accepted, SDN spec #176; RADIUS moved to v1 and dial-out to stock SoftEther servers added by #224).
- [ADR-0038](../adr/0038-web-ui-native-multi-page-with-islands.md): The web UI is native HTML, CSS and JavaScript with no build step, multi-page with interactive islands, View Transitions and Speculation Rules, embedded in the controller (Accepted, 2026-10-21).
- [ADR-0039](../adr/0039-security-hardening-baseline.md): Security hardening baseline for every Windows binary: CFG, CET, full ASLR, DEP, `/GS` and `/sdl`, `SetProcessMitigationPolicy` mitigations, virtual service accounts, strict pipe ACLs and System32-only DLL loading, pinned dependencies with an SBOM and reproducible signed builds, a BinSkim CI gate; new core only (Accepted, 2026-10-22).
- [ADR-0040](../adr/0040-ci-quality-gates.md): CI quality gates for the new core: a fuzz target per new parser, a per-module coverage floor, static analysis (clang-tidy, MSVC `/analyze` with SAL, staticcheck, govulncheck), Application Verifier and `go test -race`, and a performance regression gate (Accepted, 2026-10-22).
